# What the deployed API process needs, pinned.
#
# `pyproject.toml` stays the source of truth for what the backend *depends on*
# — the ranges, the extras, the reasons. This file is the resolution of those
# ranges that has actually been run, frozen so the EC2 box installs the same
# tree the laptop tested. Nothing here is a dev or an ETL dependency: pytest,
# ruff, mypy, pandas, duckdb and pyTigerGraph are all in the optional extras
# and none of them is imported on a request path.
#
#   python3.12 -m venv /opt/sentinel/venv
#   /opt/sentinel/venv/bin/pip install -r backend/requirements.txt
#   /opt/sentinel/venv/bin/pip install --no-deps -e ./backend
#
# The second line installs the `sentinel` and `api` packages themselves
# without re-resolving anything, so the pins below are the whole tree.
#
# `-e` is not a convenience there, it is required. `Settings.ROOT` is derived
# from the settings module's own path — backend/sentinel/config/settings.py,
# up three — and that is what anchors `cases/`, `case_pack.csv`, `runs/`,
# `exploration/rings.json` and `backend/var/`. A regular install copies the
# package into site-packages, where "up three" is a directory in the venv and
# every one of those paths silently points at nothing. Editable leaves the
# module in the checkout, so ROOT stays the checkout.
#
# To refresh after changing pyproject.toml: install the new ranges into a
# clean venv, run `python -m sentinel doctor` and the test suite against it,
# then regenerate this file from that venv.
